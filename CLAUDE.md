## Premium Build Standard

Before substantial implementation, read and follow `PREMIUM_BUILD_STANDARD.md`.

Treat it as the repository's default design and engineering quality bar unless a more specific project requirement explicitly conflicts with it.

Key expectations:

- Build for the actual user workflow, not generic SaaS aesthetics.
- Avoid obvious AI-generated UI patterns.
- Preserve good existing design and architecture.
- Use component libraries as implementation primitives rather than visual identity.
- Do not add complexity or abstraction without a concrete reason.
- Handle real states, errors, responsiveness, accessibility, security, and edge cases.
- Perform the post-implementation audits in `PREMIUM_BUILD_STANDARD.md` before declaring substantial work complete.
