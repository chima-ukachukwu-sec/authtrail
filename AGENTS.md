## Premium Build Standard

Before making meaningful product, UI, UX, frontend, backend, or architecture changes, read and follow `PREMIUM_BUILD_STANDARD.md`.

Treat it as the repository's default quality bar unless a more specific project requirement explicitly conflicts with it.

Key rules:

- Inspect the existing repository before redesigning or restructuring it.
- Preserve good existing conventions.
- Avoid generic AI-generated UI patterns and starter-template aesthetics.
- Use component libraries as primitives, not as the product's visual identity.
- Do not introduce abstractions, dependencies, layers, or architecture without a concrete need.
- Handle real states, errors, responsiveness, accessibility, security, and edge cases.
- Before declaring substantial work complete, run the post-implementation audits in `PREMIUM_BUILD_STANDARD.md`.
